# Saved FX/fuel bar and “Changed this week”

Paths and behaviour (static-export deployment):

- `app/layout.tsx` already mounts `components/live/ticker.tsx` on every route. The ticker now passes only the saved CBN USD, indicative parallel USD buy and **wholesale depot** petrol median from `data/live/fx.json` / `data/live/fuel.json` and the matching `lib/source-registry.ts` records to `components/live/micro-bar.tsx`. No fallback from dated editorial estimates is substituted for missing readings. Each card links to `/status` or `/prices/fuel` and prints its own recorded check time in WAT and verification state. `lib/micro-reading.ts` never promotes a seeded/stale reading; the client clock can only mark an older saved reading stale, without fetching or refreshing any value. The bar says it is saved, not live. A check time is not a source publication time; the source time is available in the card title and on `/status`.
- Public pages show a **single compact horizontal scroll row** on mobile, under the header (not fixed near the bottom navigation or push prompt). `/admin` and `/status` omit the bar: the latter already contains source/check times, health and history. There is no animated marquee, WebSocket or network poll.
- `app/page.tsx` inserts `components/live/changed-this-week.tsx` after the daily briefing. `lib/changed-this-week.ts` reads only `data/history.json` and generated article `updatedAt`. For a movement, two actual observations must differ, and **both source time and observation time** of the changed point must fall in the past seven days. An unchanged subsequent scrape is not a new move. Cards say which recorded values changed and link to `/status` or `/prices/fuel`; they do not claim an old movement is still the current price. Article edits use the article's real path and date, and only claim manual verification if `lastVerified` and `verification` support it. Date-only article updates are included only for complete UTC calendar days safely inside the rolling window. Up to three movements and three article edits are shown, not popularity ranks.
- **Empty state:** if no qualifying history move and no qualifying dated article edit exists: “No verified move this week. No dated article update in the last seven days either”; `/status` remains linked. On an old static export, the browser retires expired items and shows that same empty state, without making up replacements. Without JavaScript, the server-rendered page is the build-time snapshot, not a live/current feed.

Validation: `npm test` (including `lib/changed-this-week.test.ts`), `npm run typecheck`, `npm run lint`, `npm run build`, `npm run audit:static` (includes exported-shell checks); smoke `GET /`, `GET /status`, `GET /prices/fuel` and `GET /admin`. Share, Telegram, Web Push and images retain their existing paths and tests.
